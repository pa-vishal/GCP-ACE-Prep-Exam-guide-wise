🏢 Host vs. Service Project Model (Shared VPC)

Essential for Pro-level certifications and Enterprise Architecture.

The Host Project

The "Central IT" project. It contains the physical network infrastructure.

  • ✔ Owns the VPC Network & Subnets
  • ✔ Manages Firewall Rules
  • ✔ Manages Cloud Interconnect / VPN

The Service Project

The "Developer" project. It contains the application resources.

  • ✔ Owns Cloud Run / GCE / GKE
  • ✔ Pays for its own compute resources
  • ✔ Uses subnets shared from the Host

Inside vs. Outside the VPC

In GCP, resources like Cloud Run and BigQuery live in Google-managed projects. These "Bridges" allow them to securely talk to your private internal resources.

1. Serverless VPC Access

Direction: Outbound (Serverless → VPC)

  • ✔ Allows Cloud Run/Functions/App Engine to reach Private IPs.
  • ✔ Handles IP range translation between the service and VPC.

Exam Trigger Words

"Access internal database," "Private IP from Cloud Run," "Internal Load Balancer."

2. Private Google Access

Direction: Inbound (VPC → Google API)

  • ✔ VMs with only internal IPs can reach Google APIs.
  • ✔ Enabled at the Subnet level.

Exam Trigger Words

"No external IP," "Reach BigQuery from VM," "Security requirement: No Internet."

3. Private Service Connect

Modern: Endpoint Injection

  • ✔ Create a Local IP address for an external Google service.
  • ✔ Works for Google APIs or 3rd party SaaS.

Exam Trigger Words

"Specific IP for API," "SaaS integration," "Consumers and Producers."

Scenario Laboratory

Scenario: Serverless Connectivity PCA / ACE Exam Style

"Your company uses Cloud Run to host a frontend API. This API must query a Cloud SQL instance that has its public IP disabled for security compliance. How do you enable this connection?"

Correct Answer: B

Why: Cloud Run is "outside" the VPC. To talk to a Private IP "inside" a VPC, you need the Serverless VPC Access Connector. PGA (Option A) is for VPC-to-Google API traffic, not the other way around.

Scenario: Security Compliance Associate Cloud Engineer Style

"A fleet of Compute Engine instances in a high-security subnet have no external IP addresses and no Cloud NAT. They need to upload logs to a Cloud Storage (GCS) bucket. What is the most cost-effective solution?"

Correct Answer: A

Why: Private Google Access is specifically designed for VMs without public IPs to reach Google services (GCS, BigQuery, etc.) over the internal network. It's a simple checkbox on the subnet settings.

Scenario: Hybrid Architecture Pro Network/Architect Style

"Your organization wants to access BigQuery from an on-premises data center connected via Cloud Interconnect. You want to avoid using public DNS and instead use a specific internal IP address (10.1.0.50) within your VPC. What should you configure?"

Correct Answer: B

Why: PSC allows you to "inject" a specific IP from your VPC range to represent a Google service. This is ideal for hybrid scenarios where on-prem systems need a predictable, internal IP to route to for Google APIs.
