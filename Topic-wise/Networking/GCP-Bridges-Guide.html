🏢 Host vs. Service Project Model (Shared VPC)

Essential for Pro-level certifications

The Host Project

The "Central IT" project. It contains the physical network infrastructure.

  • ✔ Owns the VPC Network & Subnets
  • ✔ Manages Firewall Rules & Interconnect

The Service Project

The "Developer" project. It contains application resources like Cloud Run.

  • ✔ Owns Compute Resources & Services
  • ✔ Uses subnets shared from the Host

The Battle: PSA vs. PSC

Private Service Access (PSA)

  • Tech: Uses VPC Network Peering.
  • Setup: Reserve an IP range (e.g., 10.1.0.0/16) and create a peering connection.
  • Best for: Cloud SQL, Memorystore, Filestore.
  • Constraint: You cannot easily control the exact IP of the database; it's picked from your range.

Private Service Connect (PSC)

  • Tech: Uses Forwarding Rules (endpoints).
  • Setup: Pick one IP from your existing subnet.
  • Best for: BigQuery, GCS, published 3rd party services.
  • Strength: No peering issues (overlapping IPs are okay). Transparent to the client.

Scenario Laboratory

Scenario: Serverless Connectivity ACE / PCA Style

"Your company uses Cloud Run to host a frontend API. This API must query a Cloud SQL instance that has its public IP disabled. How do you enable this connection?"

Correct Answer: B

Why: Cloud Run exists in a Google-managed project (outside your VPC). To reach a private IP inside your VPC, you need the "bridge" provided by a Connector. PGA (Option A) is only for traffic moving from the VPC out to Google APIs.

Scenario: Air-Gapped Compliance Security / Engineer Style

"You have Compute Engine instances with no external IP addresses. They need to upload data to a Cloud Storage bucket without using a NAT Gateway. What is the most efficient solution?"

Correct Answer: A

Why: PGA allows VMs with internal-only IPs to reach Google APIs (GCS, BigQuery, etc.) through the Google network backbone rather than the public internet.

Scenario: Database Implementation Pro Cloud Architect

"You are setting up Cloud SQL for PostgreSQL. You want it accessible only via internal IPs using the native implementation that leverages VPC Peering between your network and the Google services network. What do you configure?"

Correct Answer: A

Why: Cloud SQL "Private IP" is the primary use case for Private Service Access. PSA relies on a Peering connection to a Google-managed VPC. PSC (Option B) uses Endpoints, not Peering.

Scenario: Shared VPC Hierarchy Network Engineer / Architect

"In a Shared VPC environment, you deploy a Cloud Function in a Service Project. It needs to reach a Memorystore instance in the Host Project. Where is the VPC Connector created?"

Correct Answer: B

Why: The VPC Connector must reside in the same project as the serverless resource (the Service Project). However, it is configured to attach to a network in the Host Project.

Scenario: Hybrid API Access Pro Network Style

"You want to access BigQuery from an on-prem server via Interconnect. You want to use the internal IP 10.0.1.100 from your VPC to represent the BigQuery API. What should you create?"

Correct Answer: A

Why: PSC allows you to create a "virtual endpoint" (a local IP) in your own VPC that points to a Google service. PGA (Option B) doesn't work for on-premises systems without complex workarounds; PSC is the modern solution for this.
