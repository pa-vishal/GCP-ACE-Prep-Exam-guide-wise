Cloud SQL — ACE Mental Model (One-Page)

🧠 Core Truth (anchor this first)

Cloud SQL is a Google-managed relational database.
You do not manage servers — you manage availability, connectivity, and data protection.

Everything else hangs off this.

1️⃣ Where Cloud SQL lives (MOST misunderstood)

  • Cloud SQL does NOT live inside your VPC
  • It runs in a Google-managed service network
  • You connect to it, you don’t host it

🧠 Hook: “Cloud SQL is managed by Google; you just plug into it.”

2️⃣ Availability vs Scale (must separate)

Requirement Feature
Automatic failover High Availability (HA)
More read capacity Read Replicas
Disaster recovery Backups + PITR

🧠 Hook: “HA keeps it up, replicas make it faster, backups save your data.”

3️⃣ Connectivity (how traffic flows)

Two access models:

  • Public IP

    • Simpler
    • Less secure

  • Private IP

    • Uses Private Service Access (PSA)
    • No public internet
    • Most ACE questions expect this

🧠 Hook: “Private Cloud SQL = PSA.”

4️⃣ Backups & Recovery (VERY testable)

  • Automated backups

    • Enabled per instance
    • Required for PITR

  • On-demand backups

    • Before risky changes

  • Point-in-Time Recovery (PITR)

    • Restore to a specific moment

🚫 Never use VM snapshots for Cloud SQL.

🧠 Hook: “Databases use database backups, not VM snapshots.”

5️⃣ Operations (ownership mindset)

  • Maintenance windows

    • You choose when Google patches
    • Downtime planning

  • You don’t control what is patched — only when

🧠 Hook: “Maintenance windows control timing, not content.”

6️⃣ Security layers (THIS is ACE gold)

Cloud SQL has two distinct security layers:

A. IAM — Who can connect

  • Example role: Cloud SQL Client
  • Controls instance-level access

B. Database users — What they can do

  • MySQL / Postgres users
  • Table & query permissions

🧠 Hook:

“IAM gets you in. Database users control the data.”

7️⃣ Secure connectivity (best practice)

  • Cloud SQL Auth Proxy / connectors

    • No IP allowlists
    • No passwords in code
    • Secure by default

🧠 Hook: “Secure app access → Cloud SQL proxy.”

🔑 Cloud SQL — Exam-Safe One-Liners

  • “Automatic failover” → HA
  • “Improve read performance” → Read replica
  • “Restore deleted data from earlier today” → PITR
  • “Private access from VPC” → Private IP + PSA
  • “Secure app connection” → Cloud SQL Proxy
  • “Backups” → Automated backups (not snapshots)

If you can map a question to these lines, you’ll answer correctly.
