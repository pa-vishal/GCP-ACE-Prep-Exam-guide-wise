Cloud Storage (GCS) — ACE Mental Model (One-Page Summary)

Use this as your default reasoning map whenever you see a Cloud Storage question.

🧠 Core Mental Model

Cloud Storage is an object store where you choose location, control cost over time, and secure access primarily with IAM.

Everything else is a variation of this.

1️⃣ Buckets (the container)

Bucket properties (immutable once created)

  • Location

    • Regional → latency / data residency
    • Multi-region → availability / global access

  • Uniform Bucket-Level Access (UBLA)

    • Enforce IAM-only access
    • Disable ACLs (best practice)

🧠 Rule: You can’t change a bucket’s location later.

2️⃣ Objects (the data)

  • Objects live inside buckets
  • Objects are immutable
  • New upload = new object version (if versioning enabled)

Object versioning

  • Protects against accidental deletion/overwrite
  • Costs extra storage

🧠 Rule: Versioning = safety, not access control.

3️⃣ Storage Classes (cost control)

Class When to Use
Standard Hot data
Nearline Monthly access
Coldline Yearly access
Archive Long-term retention

Key ACE nuance:

  • Colder = cheaper storage
  • Colder = higher retrieval cost
  • Access latency stays low

🧠 Rule: Cost shifts from storage → retrieval as data gets colder.

4️⃣ Lifecycle Rules (automation)

Lifecycle rules let you:

  • Transition objects to colder classes
  • Delete objects after time

ACE-safe patterns:

  • Based on object age
  • Not on access frequency

Example:

Move objects older than 90 days to Coldline

🧠 Rule: Lifecycle rules automate cost optimization.

5️⃣ Access Control (MOST tested)

IAM (preferred)

  • Applied at bucket or project level
  • Scales cleanly
  • Works best with UBLA

ACLs (legacy)

  • Object-level
  • Avoid unless explicitly required

Common roles:

  • Storage Object Viewer → read
  • Storage Object Creator → upload only
  • Storage Object Admin → full control

🧠 Rule: Modern GCS access = IAM + UBLA.

6️⃣ Temporary Access (classic ACE scenario)

Signed URLs

  • Time-limited access to an object
  • No IAM changes
  • Ideal for external users

🧠 Rule: Temporary access → Signed URL.

7️⃣ Operations & Data Movement

  • gsutil / gcloud storage → manual ops
  • Storage Transfer Service → large / cross-cloud moves
  • Native integration with BigQuery, Dataflow

🧠 Rule: Big data moves → Storage Transfer Service.

🔑 Cloud Storage — Exam-Safe One-Liners

  • “Global users” → Multi-region bucket
  • “Reduce storage cost over time” → Lifecycle rules
  • “Simplify permissions” → UBLA
  • “Temporary access” → Signed URL
  • “Prevent accidental deletion” → Object versioning

If you memorize just these, you’ll clear GCS questions.
