GSUtil allows you to manage lifecycle policies for Google Cloud Storage buckets. Lifecycle policies help automate actions such as deleting old objects or moving them to cheaper storage classes.

Basic Steps to Use Lifecycle Policies

  1. Create a JSON file defining your lifecycle policy.
  2. Apply the policy to your bucket using gsutil lifecycle set.

Example 1: Delete Objects Older Than 365 Days

{
"rule": [
{
"action": {"type": "Delete"},
"condition": {"age": 365}
}
]
}

Apply it to a bucket:

gsutil lifecycle set lifecycle.json gs://my-bucket

Example 2: Archive Objects to Nearline After 30 Days

{
"rule": [
{
"action": {"type": "SetStorageClass", "storageClass": "NEARLINE"},
"condition": {"age": 30}
}
]
}

This moves objects to a more cost-effective Nearline storage after they are 30 days old.

Example 3: Delete Objects Older Than 90 Days or with a Specific Prefix

{
"rule": [
{
"action": {"type": "Delete"},
"condition": {
"age": 90,
"matchesPrefix": ["logs/"]
}
}
]
}

This automatically deletes objects under logs/ that are older than 90 days.

Example 4: Multiple Conditions Example

{
"rule": [
{
"action": {"type": "SetStorageClass", "storageClass": "COLDLINE"},
"condition": {"age": 30}
},
{
"action": {"type": "Delete"},
"condition": {"age": 365}
}
]
}
  • Moves objects to COLDLINE storage after 30 days.
  • Deletes objects after 365 days.

Verify Current Lifecycle Policy

gsutil lifecycle get gs://my-bucket

Remove Lifecycle Policy

gsutil lifecycle clear gs://my-bucket

Notes

  • You can combine multiple rules in a single lifecycle JSON, and rules are evaluated in order.
  • Conditions can be based on age, createdBefore, number of newer versions, matchesPrefix, or matchesStorageClass.
  • Actions can include Delete and SetStorageClass.

These examples help automate storage management, reduce costs, and maintain compliance with data retention policies.
