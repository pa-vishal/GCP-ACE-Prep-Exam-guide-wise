Google Kubernetes Engine (GKE) — ACE Depth Summary Table

🧭 1. Cluster Types

Decision Option When to Choose (ACE Logic)
Cluster scope Zonal Dev / test, cost-sensitive
Regional Production, high availability
Management model Autopilot Default choice, minimal ops
Standard Only if node-level control is required

🧠 Rule: If availability matters → Regional. If no node requirements → Autopilot.

🧱 2. Node & Pod Management

Concern GKE Component What It Manages
Nodes (VMs) Node Pool VM size, count, OS
Pods ReplicaSet Ensures desired Pod count
App lifecycle Deployment Rolling updates, self-healing

🧠 Rule: Node pools manage nodes. Controllers manage Pods.

📈 3. Scaling (Very Testable)

Scaling Need Feature Scope
More traffic HPA Pods
More capacity Cluster Autoscaler Nodes (Standard only)
Autopilot scaling Automatic Pods + nodes (hidden)

🧠 Rule: Traffic → HPA. Capacity → Autoscaler.

🌐 4. Exposing Applications

Requirement Kubernetes Resource
Internal access only ClusterIP Service
Expose one service externally LoadBalancer Service
Multiple services, one IP, routing Ingress

🧠 Rule: One service → LoadBalancer. Many services → Ingress.

🔐 5. Access & Security (High ROI)

Access Need Correct Feature
Pod → GCP services securely Workload Identity
User access inside cluster RBAC
Reduce public exposure Private GKE Cluster

🧠 Rule:

IAM = outside cluster
RBAC = inside cluster
Workload Identity = Pods to GCP

🚫 6. Classic ACE Traps (Avoid These)

Trap Why It’s Wrong
Node pool recreates Pods Node pools manage nodes, not Pods
LoadBalancer for multiple services No routing, one IP per service
Service account keys in Pods Insecure, not best practice
Standard GKE for “production” by default Autopilot unless node control is required

🧠 One-Sentence GKE Mental Model (Burn This In)

“Autopilot + Regional + Deployment + HPA + Ingress + Workload Identity covers 80% of ACE GKE questions.”

If a question deviates from this, it will explicitly tell you why.
