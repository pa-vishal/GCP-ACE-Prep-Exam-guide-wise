I assume that Application vs Network load balancers are named so because of the layer they live in? What does it mean when we say Layer 4 (Network layer) load balancers?

Good question. This is where most people memorize instead of understanding.

Yes — Application vs Network load balancers are named based on the OSI model layer they operate on.

Let’s make this very clear.

🧠 The OSI Model (Only the Layers That Matter for ACE)

You only care about:

Layer Name What it Handles
7 Application HTTP, HTTPS, gRPC
4 Transport TCP, UDP
3 Network IP addressing

🔥 What Is a Layer 4 (Network/Transport) Load Balancer?

When we say Layer 4 load balancer, it means:

It makes routing decisions based only on:

  • Source IP
  • Destination IP
  • Port
  • Protocol (TCP or UDP)

It does NOT understand:

  • URLs
  • HTTP headers
  • Cookies
  • Paths
  • Hostnames

It only sees packets.

Think of it like:

“I see TCP traffic on port 3306. Send it to backend A.”

That’s it.

🎯 What Is a Layer 7 (Application) Load Balancer?

Layer 7 load balancers:

  • Understand HTTP

  • Can inspect:

    • URL path (/api vs /images)
    • Host header (app.company.com)
    • Cookies

  • Can do:

    • Path-based routing
    • Host-based routing
    • SSL termination
    • Cloud CDN
    • WAF integration

It reads the actual HTTP request.

It thinks at the application level.

🚀 Concrete Example

Layer 4 Decision:

Incoming TCP traffic on port 443
→ Send to VM group A

It does not know whether the user requested:

  • /login
  • /checkout
  • /api

It doesn’t care.

Layer 7 Decision:

Incoming HTTPS request:

GET /images/logo.png
Host: app.company.com

Load balancer can decide:

  • /api/* → Backend A
  • /images/* → Backend B

That’s application intelligence.

🔎 Why This Matters for ACE

Because exam questions hide the answer in routing requirements.

If the question says:

  • “Path-based routing”
  • “Host-based routing”
  • “Cloud CDN”
  • “HTTP headers”

→ It must be Layer 7 (Application LB).

If it says:

  • “Preserve client IP”
  • “UDP traffic”
  • “Low latency pass-through”
  • “Database TCP”

→ It must be Layer 4 (Network LB).

⚠️ Important Clarification

Technically:

Layer 4 = Transport layer
Layer 3 = Network layer

But in cloud terminology, people loosely say:
“Network Load Balancer” = Layer 4

Don’t get hung up on the naming.
For ACE, just remember:

Layer 4 = TCP/UDP
Layer 7 = HTTP/HTTPS

💡 Real-World Intuition

Layer 4 = traffic cop
Layer 7 = application-aware traffic manager

Layer 4: “Where should this packet go?”
Layer 7: “Where should this request go?”

There’s something subtle most people miss:

Layer 4 = Passthrough

The load balancer does NOT terminate the connection.
The backend VM sees the real client IP.

Layer 7 = Proxy

The load balancer terminates the connection and opens a new one to the backend.
The backend sees the load balancer’s IP unless forwarded via headers.

That difference explains:

  • Why Layer 4 preserves source IP naturally
  • Why Layer 7 enables advanced routing
